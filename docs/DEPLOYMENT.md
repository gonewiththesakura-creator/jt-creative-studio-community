# 部署、数据和升级

## 支持边界

目标为一个主人、一份本地数据、一个服务进程。Python 3.12+，Pillow 13.0.0。禁止让两台机器共享同一 SQLite 数据目录；单机第二个进程会因实例锁而拒绝启动。数据目录不要放在网络文件系统。

原服务配置、密钥、账号和历史任务不做自动迁移。此候选版不会 import 原 server.py，也不会读 config.json、panel_data 或工作流配置。

## HTTPS 远程访问

1. 保持应用端口只暴露在环回地址，使用你已管理的反向代理和域名。
2. 将 JT_PUBLIC_URL 设置为唯一 origin，例如 `https://jt.example.invalid`（示例域名不可用）。不能包含路径、查询或身份信息。
3. 代理必须保留原 Host；不要重写为内部地址。应用不会信任任意 X-Forwarded-Host / X-Forwarded-Proto。
4. 在代理设置 TLS、请求头超时和请求体限制，关闭不必要的访问日志；不要记录 Cookie、Authorization 或请求正文。
5. 不要把 8189 暴露到公网。应用使用 Python 标准库 HTTP 服务，不应独自作为互联网边缘服务器。

示例 Caddy 配置（域名替换为自己控制的域名，证书申请属于你的部署行为）：

```text
jt.example.invalid {
    request_body {
        max_size 64KB
    }
    reverse_proxy 127.0.0.1:8189
}
```

HTTPS origin 下会话 cookie 会自动带 Secure。访问地址必须与 JT_PUBLIC_URL 精确一致，因此 http/https、端口或 host 不一致会被拒绝。这是防 DNS 重绑定与跨来源请求的一部分，不是需要关闭的报错。

## 模型供应商配置

使用你自己的 HTTPS `/v1/images/generations` 地址、key 和模型。适配请求包含 model、prompt、size、quality、n=1、output_format=png。兼容方需接受这组字段及所选尺寸。不是所有宣称“OpenAI 兼容”的服务都支持 Images API 或这些参数。

不预置商用账号、不内置供应商 key、不代理 JT 原服务。不验证 key 是否有效，不自动读取用户浏览器或原生产环境凭据。配置 HTTPS 地址本身是你对目的服务的信任选择；不要填入不认识的人给的接口。

供应商图片 URL 下载仅接受公共 HTTPS 目的地，并进行 DNS 地址校验与连接绑定。带凭据的生成 POST 不跟随重定向，图片下载不携带 API key。

## 本地数据

- jobs.sqlite3 / WAL：提示词、任务状态、幂等请求 ID、收藏标记。
- images/：生成 PNG。PNG 重编码去除供应商附带的元数据。
- .instance.lock：单实例锁。

数据属于个人内容，不要提交、共享或打进容器镜像。新目录默认私有权限；运行账户和机器管理员仍能访问数据。系统不提供磁盘加密，请使用主机本身的加密与备份能力。

## 备份与恢复

最简单可靠的备份方式：等待所有任务结束，停止应用，将整个数据目录复制到你控制的安全备份位置，然后重新启动。Docker 下使用具备 volume 访问权限的管理员按 Docker volume 备份流程操作。不要在运行中仅复制 jobs.sqlite3 而漏掉 WAL。

恢复时，停止应用，把整份备份放入相同数据位置、保留运行账户可读写权限后启动。先验证任务历史与图片，再开展新生成。不要在两台设备同时运行同一份数据。

应用没有删除接口、自动清理或在线迁移。历史列表只显示最近 100 个任务，但任务账本保留以保护请求去重，旧的直接任务链接和导出仍可用。达到 10,000 个任务会拒绝新任务，需要主人先备份并规划数据维护；不要直接删账本来解除不确定任务。

## 重启与收费风险

正在运行时终止进程，重启后任务标记为结果未明，不会自动重发。即使超时计时结束，也不会假定没有收费。主人必须核对供应商后明确解除阻塞。解除阻塞不是供应商取消，不回滚费用。

每次升级先备份，运行测试，再用新的空数据目录做本地冒烟检查。此审核稿不包含生产发布器、自动部署或回滚脚本。Dockerfile 使用标签而非镜像 digest，真正发布前应固定并审查供应链版本。
